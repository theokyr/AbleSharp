# Schema Assets Catalog

## Overview
- `resources/schemas/schema-descriptors.json` provides the authoritative catalog for all bundled Ableton schema assets (197 descriptors as of v0.0.6).
- Each descriptor captures the canonical version identifier, file name, size, SHA-256 checksum, and last modified timestamp to support integrity validation and cache invalidation.
- The manifest can be regenerated by running the `tools/generate-schema-manifest.ps1` script or the equivalent PowerShell snippet documented below.

```powershell
cd C:\Projects\CSharp\AbleSharp
$schemaDir = "resources\schemas"
Get-ChildItem $schemaDir -Filter *.txt |
  ForEach-Object {
    $name = [System.IO.Path]::GetFileNameWithoutExtension($_.Name)
    if ($name -match '^(?<major>\d+)\.(?<minor>\d+)_(?<change>\d+)$') {
      $hash = Get-FileHash -Path $_.FullName -Algorithm SHA256
      [PSCustomObject]@{
        versionId = $name
        majorVersion = [int]$matches.major
        minorVersion = $matches.minor
        schemaChangeCount = [int]$matches.change
        fileName = $_.Name
        sizeBytes = $_.Length
        sha256 = $hash.Hash.ToLower()
        lastModified = $_.LastWriteTimeUtc.ToString("o")
      }
    }
  } | Sort-Object versionId | ConvertTo-Json -Depth 5 |
  Set-Content (Join-Path $schemaDir 'schema-descriptors.json')
```

## Naming and Versioning Conventions
- Schema files follow `<major>.<minor>_<schemaChange>.txt`, mirroring Ableton Live’s XML header metadata (e.g., `12.0_12203.txt`).
- Migration classes will adopt the `AbleSharp.Lib.Schema.Migrations.v<major>_<minor>_<schemaChange>To...` naming when introduced; descriptors expose both the friendly `versionId` and numeric breakdown to simplify code generation.
- Descriptor IDs are unique and case-sensitive; treat them as stable keys for caching and migration graph edges.

## Generation and Tooling Inventory
- `AbleSharp.CLI` includes a `schema` command backed by `SchemaCodeEmitter` from `AbleSharp.Schema.Generation`, mirroring the build pipeline.
- Roslyn incremental generator (`AbleSharp.Schema.Generator`) consumes `schema-generation-plan.json` and emits `AbleSharp.Lib.Schema.Generated.*` bindings and catalog metadata at compile time.
- CI drift detection remains a follow-up item; generator artifacts are now untracked sources produced during build.

## Known Divergences
- Canonical domain types under `AbleSharp.Lib` diverge from schema 12.0 feature coverage (missing properties for Simpler variants and Live 12 transport changes).
- Generated schema classes under `AbleSharp.Lib.Schema.Generated` omit remoteable polymorphism and device inheritance; manual glue code lives in feature-specific folders and needs reconciliation.
- Legacy `SchemaGenerator` implementation has been retired in favor of the source generator; remaining stub types will be reconciled during canonical model hardening.

## Acceptance Criteria for Canonical Model Validation
- Canonical model namespaces declare every element present in the latest schema descriptor; nightly validation should report missing or extra members.
- Round-trip serialization tests must succeed for every descriptor marked as `supported` (Phase 2 will track this flag in the manifest).
- Canonical types must expose XML attributes mirroring descriptor metadata (element name, optionality, collection semantics) with zero manual renames unless documented.
- Version detection leverages `SchemaRepository` descriptors, and discrepancies in hash/size invalidate caches and block migrations until resolved.
